---
name: sprint-update
description: Use when writing a weekly/sprint status update for a mentor, supervisor, or team, or when summarizing recent research progress, results, and blockers.
---

Read `docs/guides/SPRINT-UPDATE.TEMPLATE.md` and write the update from evidence:
- Lab notebook entries since the last update (ask where the notebook and the previous update are if you can't find them).
- `git log` for the same period.
- The hypothesis card, if there is one, for the "Hypothesis status" line.

Look for the cadence and where updates get posted in the lab notebook header. If they're missing, ask once and write the answer into the header.

Every number needs uncertainty and a source. If a result has neither, mark it unverified rather than dropping it. Keep it readable in under 5 minutes, and put the decisions the mentor needs to make near the top. Draft it only; posting is the user's call.
